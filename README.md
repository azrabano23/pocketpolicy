# pocketpolicy

Distil a robot policy into int8 C that runs on the microcontroller already inside the arm.

Robot foundation policies such as π0, π0.5 and OpenVLA are 10–12 GB checkpoints that need a
GPU. The $120 SO-101 arm they are demonstrated on is driven by a serial bus of $14 servos.
pocketpolicy asks how much of a big policy's skill survives when it is compressed into
something a Cortex-M class chip can run at the arm's 30 Hz control rate. It measures that
retention as a closed-loop curve, not as a loss value.

```
teacher (big) ──DAgger──► MLP student ──int8──► integer pipeline ──► C99
                                                  ticks, mm in           bit-exact vs numpy,
                                                  servo ticks out        -Werror, no malloc/float
```

## Results

All numbers are from [`results/ledger.jsonl`](results/ledger.jsonl). They are checked by
`loopgraph claims results/ledger.jsonl results/claims.json`, and the tables are regenerated by
`scripts/report.py` ([REPORT.md](results/REPORT.md)).

- **Teacher:** 98.5% success on 200 held-out pick-and-place episodes.
- **Smallest student at 90% or better:** 64×2 MLP with 2 DAgger rounds. It reaches **90.5%** in **6.4 KB** of flash and 141 B of RAM.
- **Largest student:** 97% in 144 KB.
- **Every admitted run:** the emitted C matched the integer reference byte for byte.
- **DAgger ablation (3 seeds):** DAgger adds 13–31 points of success, and the gain is largest where it is needed, in small students that drift into states the teacher never visited.

| student | behaviour cloning | + DAgger | gain |
|---|---|---|---|
| 32 × 2 | 0.295 | 0.422 | +0.127 |
| 64 × 2 | 0.507 | 0.752 | +0.245 |
| 64 × 3 | 0.562 | 0.873 | +0.312 |

The Pareto frontier was found by a committee of planning agents (a Pareto-frontier walker and a
random explorer) under a 24-run budget, through [loopgraph](../loopgraph). Two gates applied:
bit-exact C, and at most half a Cortex-M4's time at the control rate.

## What is real and what is not

- **Real:**
  - The SO-101 kinematics come from the arm's own URDF, vendored unmodified (Apache-2.0).
  - The STS3215 protocol packets are checked against an independent encoding.
  - The C builds under `-Wall -Wextra -Werror -pedantic`.
- **Stand-in:**
  - **The teacher is a scripted inverse-kinematics expert, not π0.** It is deterministic and needs no GPU, so every result here reproduces on a laptop.
  - `OpenPITeacher` wraps the openpi websocket client with the same `chunk()` interface, but has not been run. openpi ships no SO-101 normalisation stats, so it needs a fine-tuned checkpoint.
- **Not modelled:** the task simulates kinematics, servo speed limits, actuator noise, grasp and release. It does not simulate contact, slip or object dynamics.
- **Not measured:** the Cortex-M4 timings are MAC counts × 4 cycles, labelled `_est`. Nothing has run on an arm.

## Use

```bash
pip install -e ../loopgraph -e ".[test]"
pytest                                          # 21 tests
pocketpolicy campaign --budget 24               # agents search width/depth/H/DAgger
pocketpolicy ablate                             # the DAgger ablation
pocketpolicy emit --width 64 --depth 2 --H 1 --dagger 2 -o out/
```

`emit` writes `pocket.[ch]` and `pocket_net.[ch]`. `firmware/so101_main.c` reads joint positions over the servo bus, calls `pocket_step`, and streams the action chunk at 30 Hz. Board-specific I/O goes in the `hal_*` hooks.

## Layout

| file | role |
|---|---|
| `robot.py` | URDF parsing and batched forward kinematics |
| `sim.py` | batched pick-and-place task |
| `teacher.py` | scripted IK teacher, openpi adapter, chunked rollouts |
| `student.py` | numpy MLP and DAgger |
| `deploy.py` | integer pipeline and C emission |
| `gate.py` | whole-pipeline bit-exact check |
| `pipeline.py`, `cli.py` | loopgraph graph and campaigns |
| `firmware/` | STS3215 protocol and control loop |
